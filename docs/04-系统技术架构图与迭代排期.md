# 系统技术架构图 + 迭代排期表（v1 · 给领导确认）

## 一、架构分层（当前已落地，本地演示形态）

```
┌──────────────────────────────────────────────────────────────┐
│ 前端层：Gradio 7 Tab（岗位管理/简历库/初筛/面试/对比/评估/看板） │
├──────────────────────────────────────────────────────────────┤
│ 业务层：handlers.py（三个智能体编排：筛选/面试/入职运营）        │
│         · 状态机流转 · 通知渠道抽象 · 授权日志                  │
├──────────────────────────────────────────────────────────────┤
│ 算法层：algorithms.py（规则引擎/语义匹配/加分/加权，全确定性）   │
│         evaluator.py（证据链评审） interviewer.py（自适应提问） │
│         LLM 适配：config.py（DeepSeek，可换任意 OpenAI 兼容 API）│
├──────────────────────────────────────────────────────────────┤
│ 数据层：SQLite 8 表（candidates 状态机/job_profiles 规则/       │
│         notifications 发送日志/offers/screenings/interviews）  │
│         简历文件落盘 resumes/（DB 存路径+解析文本）              │
└──────────────────────────────────────────────────────────────┘
```

**分层原则已落实**：前端不碰逻辑、业务不碰算法、算法不碰数据；每层接口稳定，扩展（背调/绩效关联）只需在业务层加智能体。

## 二、生产目标架构（第三步：MySQL + ES）

```
前端（Vue/React 管理端）──▶ 业务层（FastAPI 服务化）
                              ├──▶ 算法层（打分/匹配/评审，独立服务或库）
                              └──▶ 数据层
                                     ├── MySQL：候选人全量数据（事务/审计/状态机）
                                     ├── Elasticsearch：简历全文检索（IK 分词）
                                     └── 对象存储：简历原文件（PDF/DOCX）
通知：企业微信机器人 / 短信服务商 API
面试：腾讯会议 / 飞书 API（线上面试，不自建音视频）
算法云服务：腾讯云 TI 文本匹配 / 阿里云简历解析（业务层适配，省 60% 开发量）
```

**迁移成本评估**：数据层 SQL 为标准 SQL，替换连接即可平移 MySQL；简历全文检索当前 SQLite LIKE 实现，接口 `search_candidates()` 已按 ES 适配器设计，替换内部实现即可。其余层不动。

## 三、迭代排期（MVP 优先，2 周跑通）

| 阶段 | 周期 | 内容 | 验收标准 |
|---|---|---|---|
| **M0 已完成** | — | 三智能体框架/分层打分/数据库/合规授权日志/通知渠道抽象/看板 | 147 单测全绿，本地全流程跑通 |
| **M1 MVP** | 第 1-2 周 | 平台 API 对接（1 家）+ 简历→打分→人工复核→自动通知闭环 + 企业微信通知通道 | 真实投递简历自动入库并完成初筛，通知自动触达 |
| **M2 效果验证** | 第 3-4 周 | 语义匹配层接入云 API（腾讯云 TI 或部署 SBERT）+ 打分效果对比验证（分层分 vs AI 分 vs 人工复核结论） | 产出效果验证报告：打分与人工复核一致率 ≥ 85% |
| **M3 面试升级** | 第 5-8 周 | 语音问答面试（ASR/TTS + 固定题库）→ 线上会议对接（腾讯会议/飞书）→ 防作弊（切屏检测）；**断点续面**（session 状态每轮落盘，中途退出可恢复）；**多轮筛选漏斗**（HR初筛→技术一面→技术二面→HR终面，每轮独立 prompt 与结论传递） | 候选人可用语音完成一轮 AI 面试，中断可续 |
| **M4 数字人** | 第 9-12 周 | 数字人形象 + 语音面试体验打磨 | 面试体验接近真人初面 |
| **M5 扩展** | 持续 | 入职运营深化（对接培训系统）、背调/绩效关联接口、多平台扩展 | 按业务优先级排期 |

**人力需求**：MVP 阶段 1 名全栈 + 1 名算法（可兼职）；M3 起需要 1 名前端专项。
