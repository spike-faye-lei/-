# 真实用户 POC 计划（下周启动 · 明天就干）

> 目的：用 1 个真实 HR 的原话，替代 100 个功能点。README 的"谁在用"框填上内容之前，
> 所有"能做什么"都只是代码完成度，不是业务验证度。

## 第 1 步：找 1 个 HR 试用（24 小时内完成）

| 项 | 内容 |
|---|---|
| 目标 | 1 个真实 HR + 10 份真实简历（脱敏） |
| 操作 | 全程录屏（HR 屏幕 + 语音原话） |
| 产出 | 录屏 + 用户原话记录（不加工、不解释） |
| 底线 | HR 说"我不会用" → 立刻回来改界面，不解释 |

**操作指引（给 HR 的一句话）**：你平时怎么筛简历就怎么用，我只看你自然操作，不看你的操作水平。

## 第 2 步：改到 HR 说"还行"（3 天内完成）

- 按原话反馈砍掉她不用/看不懂的功能
- 她只用了哪几个 Tab，其余默认折叠
- 记录：每次修改对应哪条原话反馈（反馈 → 改动 → 验证闭环）

## 第 3 步：再找 2 个 HR 试用（5 天内完成）

- 验证第 2 步改动是否真的变简单
- 量化指标：**从打开系统到完成第一次筛选，平均点几下鼠标**（目标 ≤ 5 下）
- 附加指标：初筛 10 份简历耗时（对比手工基线）

## 第 4 步：把用户原话写进 README

替换 README「谁在用？」占位框，格式：

```
- [x] XX 公司 HR 小王：处理 30 份简历，初筛从 3 小时缩到 45 分钟，原话："……"
- [x] XX 公司 HR 小李：原话："……"
```

## POC 评分表（自评底线）

| 项 | 通过标准 |
|---|---|
| 上手 | HR 不问任何问题完成第一次筛选 |
| 信任 | HR 看完评分卡说"这个分我能接受" |
| 效率 | 10 份简历初筛 < 10 分钟 |
| 意愿 | HR 主动说"下周再来 50 份试试" |

任一不通过 → 回到第 2 步，不进入下一阶段。

## 失败预案（诚实面对）

- 找不到 HR 试用 → 找 3 个同学/朋友扮演 HR 走一遍流程，先验证"流程讲得通"
- HR 完全不用 → 回到"HR 3 步走"最小闭环（传简历 → 等结果 → 点通过/驳回），其余全部折叠
- 反馈"AI 面试不自然" → 面试功能降级为"面试题建议 + 人工面"模式（M3 前的人工兜底）
