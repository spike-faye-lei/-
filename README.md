# AI 招聘官 Demo

企业级观感的全流程招聘智能体，覆盖招聘全链路四大环节（4 个 Tab）：

| Tab | 环节 | 说明 |
|---|---|---|
| **AI 面试官** | 面试自动化 | 主动检索 → AI 初筛 → AI 招聘官 × AI 候选人自动互聊 → 多考官证据链评分 + 雷达图 → HR 人工审核闸门 → 邀约可编辑确认发送 |
| **批量初筛** | 简历初筛助手 | 上传/粘贴多份简历 → AI 逐份评分排序 → **人工勾选复核** → 面试队列 → 一键批量面试（1000 份 = 分 50 批处理） |
| **候选人对比** | 横向对比 | 一批面试结束自动生成对比报告：各维度得分矩阵（代码计算）+ AI 推荐排序 |
| **招聘工具** | 流程自动化 | JD 生成器（自动匹配岗位 rubric）/ 面试题生成器（分级题库）/ 招聘数据看板 |

参考了行业调研（见 `research/00-summary.md`，6 份开源/商用产品研究报告），**吸收各家所长**：
- 考官风格系统（5 种风格）← AiInterview 风格矩阵
- 动态难度状态机（连续答好升难度）← AI_InterviewerAgent
- 多考官分组评审（技术/文化考官）← ats-screener
- HR 反馈校准闭环 ← Moka Eva

## 两种模式

** 全自动演示**（主推）：一键跑完——AI 自动检索简历池 → 逐份初筛 → 合适的 AI 招聘官 × AI 候选人自动互相聊天 → 出报告 → 结束自动生成横向对比。低匹配自动跳过。

** 手动模式**：上传/粘贴简历 → 手动逐轮代候选人回答 → 适合深聊一个人。

** 批量初筛 + 一键面试**：上传 10-20 份简历 → AI 评分排序表 → HR 勾选通过者 → 一键面试队列（复用同一面试循环）→ 对比报告自动入库。

## 企业级设计（演示亮点）

1. **岗位配置（rubric）**：3 个预置岗位（AI应用开发/后端/前端），评估维度与权重按岗位定制，评分规则硬约束（如"无 AI 经验技术能力≤5 分"）
2. **懂技术的资深专家考官**：默认"技术深挖"风格——追问具体实现/参数/量化指标，识别含糊回答，用具体问题验证吹牛（"QPS怎么测出来的"），不是只会念问题的 HR
3. **考官风格系统**：技术深挖 / 温和引导 / 压力面试（节奏快+犀利质疑+专挑漏洞）/ 快速筛选 / 行为面试（STAR），风格化追问话术
4. **动态难度状态机**：连续 2 次答好 → 问题升难度（基础→进阶→深度）；连续答差 → 降难度
5. **证据链评分**：每个维度分数必须附候选人原话/简历原文证据；加权总分由代码计算（确定性，不依赖 LLM 算数）
6. **多考官分组评审**：技术考官（懂技术，识深浅）× 文化考官（沟通/动机），分组评分 + 分组权重展示
7. **评分雷达图**：候选人能力可视化
8. **HR 人工审核闸门**：AI 只给建议和证据，HR 一键通过/驳回 + 留意见，通过则发送线下面试邀约（AI 不决定，人决定）；批量面试的候选人进入**待审核队列**（落库持久化），可从库中载入逐条审核，刷新/重启不丢
9. **HR 反馈校准闭环**：审核意见自动进入岗位配置，后续候选人评估参考校准（对标 Moka Eva）
10. **合规声明**：演示环境仅使用公开信息与内置模拟数据；生产环境须候选人授权同意（PIPL）
11. **面试官质量**：回答含糊必连续追问；绝不重复提问；绝不编造简历外项目；最后一轮强制收口给结论+邀约
12. **分数稳定性**：评估用低 temperature + 代码算加权分，同简历多次运行分数一致
13. **岗位采集爬虫（演示版）**：联网模式抓取 V2EX 酷工作公开招聘帖 / Gitee 公开仓库 → 按 JD 关键词自动匹配岗位 rubric → 检索候选人进入评估；只采集**自愿公开发布**的信息、走公开 API、限速礼貌抓取，失败自动回退内置数据（仅用于本地功能演示，不代表完整合规方案，生产环境须接入官方授权接口）
14. **面试维度覆盖检查**：每轮提问代码侧关键词归类到评估维度（省一次 LLM 调用），未考察维度注入 prompt 优先补问，保证各维度都被考察
15. **多人横向对比**：一批面试结束自动生成对比矩阵（代码计算，确定性）+ AI 推荐排序与综合评语
16. **批量初筛 + 人工复核闸门**：多份简历 AI 评分排序 → HR 勾选 → 面试队列一键批量面试（AI 只建议，人决定）
17. **流程自动化工具链**：JD 生成器（自动匹配岗位 rubric）、面试题生成器（分级题库）、邀约文本可编辑确认发送、招聘数据看板
18. **结论-草稿一致性守卫**：HR 审核结论与 AI 决策相反时，通知草稿自动按 HR 结论重新起草（LLM 失败回退固定模板）；审核单选默认值跟随 AI 决策——防止"结论通过、通知却是婉拒信"的矛盾记录
19. **国内网络零外链**：主题显式指定系统字体栈（阻止 Gradio 6 前端运行时注入 Google Fonts 样式表）+ 关闭 Gradio analytics——页面不依赖任何境外资源，无需 VPN 即可打开

## 配置

API key 在 `.env`（`DEEPSEEK_API_KEY`），默认模型 `deepseek-chat`，可改 `DEEPSEEK_MODEL`。

## 登录鉴权

默认免登录（本机演示模式，启动时会打印提醒）。**对外部署前**在 `.env` 中同时配置：

```
ADMIN_USERNAME=hr
ADMIN_PASSWORD=你的强密码
```

重启后访问页面需输入账号密码（Gradio 内置登录页 + 访问令牌 Cookie）。两者都配置才生效，只配一个或都不配则保持免登录。

## 文件结构

- `app.py` — 入口：初始化数据库 + 启动（含可选登录鉴权，`.env` 配置 `ADMIN_USERNAME`/`ADMIN_PASSWORD` 启用）
- `ui.py` — Gradio 界面装配（4 个 Tab：AI 面试官/批量初筛/候选人对比/招聘工具的组件与事件绑定）
- `handlers.py` — 全部事件处理函数（业务接线，纯函数 + generator，不持有组件引用）
- `ui_theme.py` — 全局样式 token（CSS）/ 合规声明 / 静态资源路径
- `bulk_screen.py` — 批量简历初筛（LLM 评分 + 代码加权 + 排序 generator）
- `compare.py` — 多候选人横向对比（对比矩阵 + LLM 推荐排序）
- `jd_generator.py` — JD 生成 + rubric 匹配 + 面试题库生成
- `llm_utils.py` — LLM 输出 JSON 容错解析 + 分数钳制（共用工具）
- `candidates.py` — 内置候选人简历库（模拟主动检索）
- `crawler.py` — 岗位采集爬虫（V2EX + Gitee 公开信息，演示版，失败自动回退）
- `job_profile.py` — 岗位配置 rubric（维度/权重/规则/覆盖检查关键词）
- `candidate_bot.py` — 候选人 AI 模拟器（简历人设）
- `resume_parser.py` — 简历解析 + 自动初筛
- `interviewer.py` — AI 招聘官（阶段推进、含糊追问、维度覆盖跟踪、收口邀约）
- `evaluator.py` — 证据链评分 + 评估数据看板图 + 筛选决策
- `file_parser.py` — PDF/DOCX/TXT 简历提取文本
- `config.py` — DeepSeek API 封装（含流式）
- `db.py` — SQLite 持久化（面试/初筛/批次/反馈/统计）
- `start.bat` — 一键启动：装依赖 + 备份数据库到 `backups/` + 打开浏览器
- `demo_resumes/` — 内置演示简历（TXT/DOCX/PDF 三种格式，可演示上传解析）
- `tests/` — pytest 单元测试（全 mock，不调真实 API）+ 3 条 live 冒烟测试（opt-in，见「测试与质量检查」）
- `research/` — 6 份行业研究报告 + 总报告
- `ruff.toml` — 静态检查配置；`.github/workflows/ci.yml` — push 自动跑 ruff + 单测
